# Настройка предложки и модерации стены

Публичная форма доступна во вкладке «Стена». Предложения стримеров и публикации (текст и/или изображение) получают статус `pending` и не видны посетителям до одобрения.

## Хранение заявок через Cloudflare R2 (рекомендуется для Render без диска)

R2 хранит заявки отдельно от Render, поэтому данные сохраняются при перезапусках и деплоях. PostgreSQL не нужен. R2 включается автоматически, когда заданы все четыре обязательные переменные:

- `R2_ACCOUNT_ID` — Cloudflare Account ID.
- `R2_BUCKET_NAME` — имя созданного R2 bucket.
- `R2_ACCESS_KEY_ID` — Access Key ID для R2.
- `R2_SECRET_ACCESS_KEY` — Secret Access Key для R2.

Не публикуйте ключи и не добавляйте их в GitHub. Создайте в Cloudflare R2 bucket класса Standard и отдельный API token/ключ с правами чтения и записи только для этого bucket. Endpoint по умолчанию формируется из Account ID; при необходимости можно задать `R2_ENDPOINT`. Имя объекта по умолчанию — `community-submissions.json`; при необходимости задайте `R2_OBJECT_KEY`.

### Подключение

1. В Cloudflare Dashboard откройте **Storage & databases → R2**, активируйте R2 и создайте bucket.
2. Создайте R2 API credentials с правами чтения/записи для этого bucket. Скопируйте Account ID и ключи.
3. В Render → ваш Web Service → **Environment** добавьте четыре обязательные переменные выше.
4. Сохраните изменения и дождитесь завершения деплоя.
5. Проверьте отправку тестовой заявки и убедитесь, что объект `community-submissions.json` появился в bucket.

Если объект в R2 ещё не существует, приложение попробует перенести туда существующий локальный JSON-файл (если он доступен). После включения R2 основным источником данных станет R2. Если R2 настроен, но временно недоступен, приложение не подменит ошибки пустым списком — операции завершатся ошибкой, чтобы избежать случайного затирания данных.

Если переменные R2 не заданы, приложение продолжит использовать локальный JSON-файл. На Render без Persistent Disk локальные данные могут пропасть при перезапуске или новом деплое. Не включайте R2, пока не проверили, что нужные старые заявки доступны в R2 или локальном файле.

## Альтернативное локальное хранение

Если используете Persistent Disk, задайте в Render `WALL_DATA_DIR=/var/data` и добавьте диск с mount path `/var/data`.

## Пароли модерации

В Render Environment задайте:
- `WALL_ADMIN_PASSWORD` — уникальный длинный пароль владельца (не используйте пароль от GitHub).
- `WALL_MODERATORS` — JSON-объект логинов выбранных модераторов и их индивидуальных паролей, например:
  ```json
  {"mod_one":"уникальный-длинный-пароль-1","mod_two":"уникальный-длинный-пароль-2"}
  ```

Вход владельца: логин `admin` и пароль из `WALL_ADMIN_PASSWORD`. Модераторы входят по логину-ключу и соответствующему паролю из `WALL_MODERATORS`. Для удаления доступа удалите запись модератора и выполните redeploy. Активные сессии живут до 12 часов или до выхода.

## Что умеет предложка

- Принимает никнейм автора без регистрации.
- Принимает ссылку Twitch для предложения стримера.
- Принимает текст и/или изображение JPG, PNG, WEBP, GIF до 2 МБ для стены.
- Ограничивает отправку с одного IP пятью заявками в час и проверяет тип/сигнатуру изображения.
- Даёт вошедшим модераторам одобрить, отклонить или удалить ожидающую заявку.
- Показывает на сайте только одобренные предложения и публикации.
